# Phase 1 report: real VST3 plugins load and render on the phone

**Result: 4 of 4 plugins load and render offline in both editions on the Galaxy S26 Ultra, and every rendered WAV is bit-identical to the same render on a native x86_64 PC.**

Measured 2026-11-18 on SM-S948U1 (SM8850, Android 17), driven over adb with the app's Phase 1 autorun. Raw device reports: [results/phase1-report-play.md](results/phase1-report-play.md) and [results/phase1-report-sideload.md](results/phase1-report-sideload.md). The rendered WAVs are in `results-audio/phase1/` (not in git; 4 × 8.8 MB).

## Setup

- **Host:** `vstghost-host.exe`, our own x86_64 Windows exe (MinGW, Steinberg `pluginterfaces` 3.8.1 headers only, MIT). One process per `info`/`render` call, all inside one long-lived Wine session.
- **Stack:** Wine 11.0 (headless, null graphics driver) + Box64 0.4.4 on the phone. The PC reference uses the same host, Wine and prefix running natively on x86_64 (WSL2, i9-14900HX).
- **Test material:** `tests/phase1.mid` (generated by [tools/make_test_midi.py](../tools/make_test_midi.py)): 20 s, 60 notes, velocity ramp, chords with sustain pedal, fast low/high repeats, pitch-bend and mod-wheel sweeps, then a held chord, + 3 s tail. The effect gets the host's built-in test signal (plucks, bass, noise hits).
- **Render settings:** 48 kHz, 256-frame blocks, VST3 offline mode, 32-bit float WAV out.

Phone numbers are from the Play edition run. The sideload run gave the same results within noise (e.g. Odin2 27.4× vs 27.1×), apart from one block-time outlier (Brass Knuckles max 8.9 ms). Both editions' WAVs were compared with [tools/compare_wav.py](../tools/compare_wav.py): `identical=True max_abs_diff=0` for all 8.

Details from every plugin:
- All are JUCE-based, with a separate controller and `IMidiMapping`. All 60 notes and **412/412** CC / pitch-bend events (sustain pedal, mod wheel, bend) were routed to parameters through `IMidiMapping`; none were unmapped.
- No NaN/Inf samples, no silent outputs, no crashes, no timeouts. 0 SELinux denials.
- Odin2's output peaks at +2.0 dBFS on the 7-note final chord with its default patch. That's the patch being loud (the PC render is identical), not a bridge fault.

## What it means for the next phases

- **Correctness:** Box64's translation of these plugins' DSP, including MSVC-compiled SSE/AVX paths, produced exactly the same samples as real x86_64. That's strong evidence that emulation won't colour the sound.
- **Speed:** on one core the phone renders 27–82× faster than real time. At 256 frames that's a p99 of 0.11–0.44 ms per block against a 5.33 ms budget. Comparing phone and PC (whose CPUs ran our scalar Phase 0 kernel at nearly the same speed) puts Box64's cost on real plugin DSP at roughly **2.3–3.3×**. That's an estimate: the two CPUs aren't identical.
- **Spikes:** worst-case blocks reached 2.2–8.9 ms, so one exceeded the 5.33 ms budget. These happen early in a render, which fits Box64 translating code the first time it runs. **Phase 2 must pre-roll** each plugin (render some silence after loading, before going live) and keep the ring-buffer prefill described in ARCHITECTURE.md.
- **Load time:** 0.12–0.18 s per plugin (Odin2 0.9 s, mostly its wavetable setup) inside a running Wine session. Fine for loading a slot.
- **Memory:** 150–230 MB RSS per plugin host process, on top of the Wine session. Four simultaneous plugins would be about 0.7 GB of RSS (summed RSS overcounts shared pages). Grouping several plugins into one host process (yabridge-style) is an option if that becomes a problem.
- **Parameters:** every JUCE plugin reports about 2,080 extra "MIDI CC n|m" parameters (JUCE's CC emulation) that aren't flagged hidden. The generic UI (Phase 2) and AAP slot parameters (Phase 3) must filter them, keeping `kCanAutomate` parameters and dropping the `MIDI CC` ones. That leaves 98–349 real parameters per plugin.
- **Headless Wine works for loading and processing.** It needed Wine's `null` graphics driver (`HKCU\Software\Wine\Drivers\Graphics=null`). Without it, Wine refuses ordinary window creation, which JUCE uses for its hidden message window.

## Issues found and fixed in Phase 1

1. **Headless window creation:** prevented up front by baking `Graphics=null` into the prefix, after reading Wine's `nodrv_CreateWindow`.
2. **Effects rendered silence when MIDI was also given:** the host fed its test signal only when there was no MIDI. Fixed: effects always get audio input, and MIDI still goes to their event bus.
3. **`adb push` of a folder into a not-yet-existing `plugins/` folder** turns the folder *into* `plugins/`. The test steps now create the folder first.
4. **WAVs written by the app aren't readable by `adb pull`** (private file mode). The test steps stream them with `adb exec-out run-as … cat`.

## Not covered by Phase 1 (by design)

Real-time audio, live MIDI, IPC and the latency measurements belong to Phase 2. Plugin GUIs belong to Phase 4. The WebView-based editors of the three newer plugins will need WebView2 under Wine, which is a known hard area to plan for in Phase 4. Copy protection: none of these plugins use any.
